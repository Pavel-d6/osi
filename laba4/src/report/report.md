## 2. Задание (вариант 6)

Родительский процесс создаёт дочерний. Первой строкой пользователь вводит в консоль родителя имя файла. Родитель открывает файл на чтение, и им переопределяется стандартный поток ввода дочернего процесса. Дочерний процесс передаёт результат родителю, родитель выводит его в свой stdout. Родитель и дочерний процесс — разные программы.

В файле записаны строки вида `число число число<endline>`. Дочерний процесс считает сумму чисел каждой строки (тип `int`, количество чисел произвольно).

В отличие от ЛР №2, данные от ребёнка к родителю передаются не через `pipe`, а через общую отображаемую память. Синхронизация выполняется семафорами и сигналом `SIGCHLD`.

## 3. File mapping

Системный вызов `mmap` отображает файл или объект общей памяти в адресное пространство процесса: после него содержимое объекта доступно как обычный массив байтов. При флаге `MAP_SHARED` несколько процессов, отобразивших один объект, работают с одними и теми же физическими страницами, поэтому запись одного процесса сразу видна другому. Данные при этом не копируются через ядро на каждую передачу.

Отличие от канала: у общей памяти нет встроенной синхронизации и признака конца данных. Ядро не блокирует читателя, пока данных нет, и не сообщает EOF. Поэтому очерёдность доступа обеспечивается семафорами, а конец данных — договорённостью (длина порции 0).

Анонимное отображение (`MAP_ANONYMOUS`) наследуется при `fork`, но теряется при `exec`. Так как ребёнок — отдельная программа, используется именованный объект POSIX shared memory (`shm_open`), который дочерняя программа открывает заново по имени.

## 4. Используемые системные вызовы

| Вызов | Назначение |
|-------|-----------|
| `open` / `close` | открытие входного файла, закрытие лишних дескрипторов |
| `shm_open` / `shm_unlink` | создание/открытие и удаление объекта общей памяти |
| `ftruncate` | задание размера объекта общей памяти |
| `mmap` / `munmap` | отображение общей памяти в адресное пространство и снятие отображения |
| `sem_open` / `sem_close` / `sem_unlink` | именованные семафоры: создание, закрытие, удаление |
| `sem_wait` / `sem_post` | захват и освобождение семафора (синхронизация) |
| `sigaction` | установка обработчика `SIGCHLD` |
| `fork` | создание дочернего процесса |
| `dup2` | подмена stdin ребёнка файлом |
| `execl` | запуск программы `child` в дочернем процессе |
| `read` / `write` | чтение имени файла и входных данных, вывод |
| `waitpid` | ожидание завершения ребёнка (нет зомби), получение кода выхода |
| `exit` | завершение процесса при ошибке |



На macOS безымянные семафоры (`sem_init`) не поддерживаются (возвращают `ENOSYS`), поэтому используются именованные (`sem_open`).

## 5. Описание алгоритма

### Общая память (`common.h`)

```c
struct shared {
    int  state;        // 1 — в буфере порция от ребёнка, 0 — буфер прочитан
    int  len;          // число байт в data; 0 — конец данных
    char data[4096];
};
```

Семафоры:
- `full` (начальное значение 0) — «данные готовы»;
- `empty` (начальное значение 1) — «буфер свободен».

Это схема «производитель–потребитель» с одним буфером: ребёнок — производитель, родитель — потребитель.

### parent.c
1. Читает имя файла посимвольно через `read(0, &c, 1)` до `\n` или EOF. Пустое имя — ошибка.
2. Открывает файл `open(name, O_RDONLY)`.
3. Удаляет объекты, оставшиеся после возможного аварийного запуска (`shm_unlink`, `sem_unlink`), затем создаёт общую память: `shm_open` → `ftruncate` → `mmap(MAP_SHARED)`, и семафоры `full = 0`, `empty = 1`.
4. Устанавливает обработчик `SIGCHLD` (до `fork`, чтобы не пропустить сигнал). Обработчик делает `sem_post(full)`, чтобы разбудить родителя, если ребёнок завершился, не отправив данные.
5. `fork`. В ребёнке: `dup2(fd, 0)`, `close(fd)`, `execl("./child", "child", NULL)`.
6. В родителе цикл:
   - `sem_wait(full)`;
   - если `state != 1` — родителя разбудил `SIGCHLD`, данных нет, значит ребёнок завершился аварийно;
   - если `len == 0` — конец данных, выход из цикла;
   - иначе `write(1, data, len)`, `state = 0`, `sem_post(empty)`.
7. `waitpid`, `munmap`, `sem_close`, удаление общей памяти и семафоров. Если ребёнок завершился с ошибкой — сообщение `child terminated with error` и код выхода 1.

### child.c
1. Открывает общую память по имени (`shm_open` + `mmap`) и семафоры (`sem_open` без `O_CREAT`).
2. Читает stdin блоками по 4096 байт и разбирает поток символов конечным автоматом, не храня строку целиком (длина строки и количество чисел не ограничены). Состояние (`sum`, `cur`, `in_num`, `neg`, `dirty`) сохраняется между вызовами `read`, поэтому число, разрезанное границей блока, собирается правильно:
   - цифра → `cur = cur * 10 + (c - '0')`;
   - `-` перед числом → признак отрицательного числа;
   - разделитель → число прибавляется к `sum`;
   - `\n` → вывод суммы через `print_num` и обнуление; пустые строки пропускаются (`dirty`);
   - после EOF дописывается последняя строка без `\n`.
3. `print_num` переводит число в ASCII с конца буфера (`u % 10 + '0'`) и добавляет его в локальный буфер вывода. Когда очередное число не помещается, буфер отправляется родителю функцией `send_block`: `sem_wait(empty)` → копирование в `data`, `len`, `state = 1` → `sem_post(full)`.
4. После обработки всего ввода отправляется остаток буфера и пустая порция (`len = 0`) — признак конца данных.

## 6. Обработка ошибок

Проверяется результат каждого системного вызова (`read`, `write`, `open`, `shm_open`, `ftruncate`, `mmap`, `sem_open`, `sem_wait`, `sem_post`, `sigaction`, `fork`, `dup2`, `execl`, `waitpid`). При ошибке выводится сообщение вида `error open file: No such file or directory` в stderr и процесс завершается с кодом 1. `EINTR` (прерывание сигналом) не считается ошибкой, вызов повторяется. Частичная запись обрабатывается в `write_full`.

Если ребёнок завершился, не дойдя до конца протокола (ошибка `execl`, ошибка внутри `child`, завершение сигналом), родитель не зависает на `sem_wait`: его будит обработчик `SIGCHLD`. При ошибке родитель удаляет созданные объекты общей памяти и семафоры, чтобы они не оставались в системе.


## 7. Компиляция и запуск

```
gcc -Wall -Wextra parent.c -o parent
gcc -Wall -Wextra child.c  -o child
./parent
data.txt
```

На Linux дополнительно нужен флаг `-pthread` (семафоры).

## 8. Выводы

В работе реализовано взаимодействие двух отдельных программ через общую отображаемую память (POSIX shared memory + `mmap`). Изучено, что отображение с `MAP_SHARED` даёт процессам общие физические страницы, и данные передаются без копирования через ядро. В отличие от канала, общая память не синхронизирует процессы и не сообщает о конце данных. Поэтому был реализован протокол «производитель–потребитель» на двух семафорах и признак конца данных (порция длины 0). Также показано, что анонимное отображение не переживает `exec`, и для отдельной дочерней программы нужен именованный объект. Обработчик `SIGCHLD` защищает родителя от вечного ожидания при аварийном завершении ребёнка. Потоковая обработка ввода, как и в ЛР №2, снимает ограничение на длину строки и количество чисел.
