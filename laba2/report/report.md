## 1. Цель работы

## 2. Задание (вариант 6)

Родительский процесс создаёт дочерний. Первой строкой пользователь вводит в консоль родителя имя файла. Родитель открывает файл на чтение, и им переопределяется стандартный поток ввода дочернего процесса. Стандартный поток вывода дочернего процесса перенаправляется в `pipe1`. Родитель читает из `pipe1` и выводит прочитанное в свой stdout. Родитель и дочерний процесс — разные программы.

В файле записаны строки вида `число число число<endline>`. Дочерний процесс считает сумму чисел каждой строки (тип `int`, количество чисел произвольно) и выводит её в stdout.

## 3. Схема взаимодействия

```
                    parent                                  child
 клавиатура ──► [имя файла]
                  open(файл) ───── fork ─────────────►  dup2(fd, 0)   stdin  ◄── файл
                  pipe(p)                               dup2(p[1], 1) stdout ──► pipe1
 экран ◄── write(1) ◄── read(p[0]) ◄───────── pipe1 ◄───────────────┘
```

Таблица дескрипторов ребёнка перед `exec`:

| fd | Указывает на |
|----|--------------|
| 0  | открытый файл с данными |
| 1  | конец записи pipe1 |
| 2  | терминал (stderr) |

## 4. Используемые системные вызовы

| Вызов | Назначение |
|-------|-----------|
| `pipe` | создание канала |
| `open` / `close` | открытие файла, закрытие лишних дескрипторов |
| `fork` | создание дочернего процесса |
| `dup2` | подмена stdin и stdout ребёнка |
| `execl` | запуск программы `child` в дочернем процессе |
| `read` / `write` | чтение имени файла, данных из канала, вывод |
| `waitpid` | ожидание завершения ребёнка (нет зомби) |
| `exit` | завершение процесса при ошибке |

Согласно требованиям курса, функции `stdio.h` (`printf`, `fgets`, `perror` и др.) не используются: ввод-вывод выполнен через `read`/`write`, сообщения об ошибках формируются через `strerror(errno)` и `write(2, ...)`, число переводится в текст вручную.

## 5. Описание алгоритма

### parent.c
1. Читает имя файла посимвольно через `read(0, &c, 1)` до `\n` или EOF. Пустое имя — ошибка.
2. Создаёт канал `pipe(p)`.
3. Открывает файл `open(name, O_RDONLY)`.
4. `fork`. В ребёнке: `dup2(fd, 0)`, `dup2(p[1], 1)`, закрытие `fd`, `p[0]`, `p[1]`, `execl("./child", "child", NULL)`.
5. В родителе: закрывает `fd` и `p[1]` (иначе `read` никогда не вернёт 0), в цикле `read(p[0])` → `write(1)` до EOF, затем `close(p[0])` и `waitpid`.

### child.c
Читает stdin блоками по 4096 байт и разбирает поток символов конечным автоматом, не храня строку целиком (длина строки и количество чисел не ограничены). Состояние (`sum`, `cur`, `in_num`, `neg`, `dirty`) сохраняется между вызовами `read`, поэтому число, разрезанное границей блока, собирается правильно:

- цифра → `cur = cur * 10 + (c - '0')`;
- `-` перед числом → признак отрицательного числа;
- разделитель → число прибавляется к `sum`;
- `\n` → вывод суммы через `print_num` и обнуление; пустые строки пропускаются (`dirty`);
- после EOF дописывается последняя строка без `\n`.

`print_num` переводит число в ASCII с конца буфера (`u % 10 + '0'`), затем выводит одним `write`.

## 6. Обработка ошибок

Проверяется результат каждого системного вызова (`read`, `write`, `pipe`, `open`, `fork`, `dup2`, `execl`, `waitpid`). При ошибке выводится сообщение вида `open: No such file or directory` в stderr и процесс завершается с кодом 1. `EINTR` (прерывание сигналом) не считается ошибкой, вызов повторяется. Частичная запись обрабатывается в `write_full`.

## 9. Выводы

В работе реализовано взаимодействие двух отдельных программ через неименованный канал. Изучено, что `fork` копирует таблицу дескрипторов, `exec` её сохраняет, а `dup2` позволяет подменить стандартные потоки так, что дочерняя программа не знает об источнике и приёмнике данных. Показана необходимость закрывать неиспользуемые концы канала: иначе читатель не получит EOF и зависнет. Потоковая обработка ввода позволила снять ограничение на длину строки и количество чисел.
